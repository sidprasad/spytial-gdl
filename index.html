Lightweight interactive graphs (with semantics!)

Describe nodes, edges, and the spatial relationships that matter. Embed the graph in your documents. Readers can move it while those relationships stay intact.

01

Have your agent use it.

A graph description language for your documents. Give your agent this prompt, or add it to your project's agent instructions:

Read https://www.siddharthaprasad.com/spytial-gdl/AGENTS.md
Use spytial-gdl when a graph would help explain the documents you write. Describe the nodes and edges, and add spatial rules where position carries meaning. Set up the renderer for this project and check the result in a browser. If the document cannot run it, link to a live diagram instead.
Read the agent guide

Already using Mermaid or Graphviz?

Give your agent the existing graph and this prompt:

Read https://www.siddharthaprasad.com/spytial-gdl/AGENTS.md
Convert this Mermaid flowchart or Graphviz DOT graph to spytial-gdl. Preserve its nodes, edges, and labels where supported, and explain any differences. Add the spatial rules that matter, embed it in this project, and check that it renders.

Conversion, not a drop-in replacement. DOT needs translation; Mermaid sequence diagrams, Gantt charts, and other non-graph formats need a different renderer.

02

Put a graph in your documents.

Paste this into an HTML page served by your site or local server:

<div class="spytial-gdl">
mul[×] -> div[÷] : lhs
mul -> three[3] : rhs
div -> six[6] : lhs
div -> two[2] : rhs

@orientation(selector=lhs, directions=[below, left])
@orientation(selector=rhs, directions=[below, right])
</div>

<script type="module"
  src="https://cdn.jsdelivr.net/npm/spytial-gdl/src/auto.js"></script>
See it running Set up your docs site

For Markdown, add the same script to your site template and use a spytial-gdl code fence. GitHub README files and PR descriptions do not run the renderer. Link to the live graph or include an exported image there.
