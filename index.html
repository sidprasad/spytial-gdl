Before Mermaid

```mermaid
flowchart LR
  Client -- calls --> API
  API -- reads --> Cache
  API -- reads --> Database
```
→

After spytial-gdl

```spytial-gdl
client[Client] -> api[API] : calls
api -> cache[Cache] : reads
api -> db[Database] : reads

@orientation(selector=_links,
  directions=[right])
```

Why this exists

The graph is data. The layout is a claim.

A useful diagram should say why things are positioned—not just remember where a renderer happened to put them.

01

Rules target meaning

Apply layout to relations, types, and classes instead of individual shapes.

02

Interaction stays valid

Drag nodes and the constraint solver settles the graph without discarding its rules.

03

Conflicts stay visible

When requirements cannot all hold, the diagram reports the conflicting rules.

Start with a graph. Add only the rules you mean.
