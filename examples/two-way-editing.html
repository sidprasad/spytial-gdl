Two-way editing

The notation and the diagram are two views of one graph. Editing either one updates the other.

Usually a diagram and the text that produced it come apart the moment someone moves a box. A spytial-gdl diagram is rendered from a small text notation — nodes, edges, and inline spatial rules — and the rendering stays attached to it. Edit the picture and the notation is re-derived from the edited graph.

Where the layout comes from

Nothing above gave a coordinate. The notation states relationships, and an inline rule — @orientation — says which way each kind of edge should point. Spytial solves for positions that satisfy those rules, which is why the shape survives being dragged around.

The next one is a binary tree: every edge points down, left edges also point left, right edges point right. Add a relation named left or right and it places itself.

Reading the graph from code

getSource() returns the notation; getValue() returns the same graph as JSON — its atoms and relations. Both update on every edit, so a page can react to what the reader did.

A node's id is what edges reference. A [label] only changes what the node is called on screen, which is why the people below have names while the edges still wire up by id.

Getting it back out

copy notation on any figure gives you plain text to paste into a doc, a commit message, or an issue. Put it back on a page as a ```spytial-gdl block and it renders again; tag the block ```spytial-gdl-editable and readers get the version you have been using here.
